Hopper

Route Click’n’Load and .dlc downloads to a remote hopperd.

Your hopperd host. Only the hostname is used — Click’n’Load redirects always go to port 9666, .dlc import always goes to port 9667 (the API port), regardless of the port typed here. hopperd's own CnL listener stays plain HTTP, so the redirect destination keeps whatever scheme you type here (usually http://) — only the local address this intercepts changed, from http://127.0.0.1:9666 to https://127.0.0.1:9666, to match what an HTTPS hoster page's Click’n’Load button actually targets (browsers block a plain-HTTP request from an HTTPS page as mixed content).

Only needed for automatic .dlc (and optional .txt) import — Click’n’Load redirection works without one. Obtain a token by logging in (hopperctl login or the Web UI) and copying it from ~/.config/hopper/hopperctl.json (Linux/macOS) or %APPDATA%\hopper\hopperctl.json (Windows). Tokens expire after server.token_ttl (24h by default) — set it longer in hopper.yaml if you rely on this. Stored locally on this device only, never synced.

Off by default: every .txt download containing a link would be sent to hopperd and removed from your downloads, not just link lists.
